# 01 需求说明：素材审核与发布排期 Agent

## 1. 用户与目标

- **目标用户**：内容团队的运营/审核人员。
- **业务目标**：帮助团队从待处理素材中找出可发布对象，形成无冲突、可确认的发布排期。
- **系统边界**：系统只保存排期草稿，不接真实发布；任何"已发布"状态都不在本系统范围内。

## 2. 输入与材料

- 素材 ID、素材元数据（标题、类型、时长）、发布时间要求（含是否为硬性要求）。
- 已有排期与审核规则。
- 四个业务工具：素材读取、规则检查、时段查询、排期草稿保存。

## 3. 交付结果

对每项素材输出：

1. 审核状态（approved / blocked / pending_confirmation / incomplete）。
2. 风险原因。
3. 建议时段。
4. 待确认项。
5. 草稿保存状态。

## 4. 范围

**包含**：单素材的 ReAct 审核排期闭环、离线 Mock 决策、真实大模型接口预留、可执行测试与运行 Trace。

**不包含**：用户界面、线上部署、多 Agent 协作、生产级 Runtime、真实发布动作（题目说明均非必需）。

## 5. 成功标准（验收点）

| 编号 | 验收点 | 成功标准 |
|---|---|---|
| A1 | 正常排期 | 无风险素材在空闲时段保存草稿，状态 approved |
| A2 | 素材信息缺失 | 先补查，补查无法补全则阻断，不产生草稿 |
| A3 | 规则风险 | 命中规则时阻断并给出风险原因 |
| A4 | 时段冲突 | 建议替代时段并标记待确认，用户确认后才保存 |
| A5 | 重复提交 | 同一素材重复提交只产生一份草稿 |
| A6 | 保存失败 | 明确返回失败，不虚报保存成功 |

## 6. 硬性约束

- 未经用户同意，不得擅自改变硬性发布要求。
- 只能保存草稿，不能标记为已发布。
- 必须设置执行步数/工具调用次数上限，超限返回明确的未完成状态。
