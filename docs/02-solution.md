# 02 方案设计：调用流程、动态决策与技术取舍

## 1. 总体结构

```
run.py（CLI 入口）
  └── src/agent.py        ReAct 主循环：模型选动作 → 执行工具 → 观察 → 再决策
        ├── src/llm.py    MockLLM（离线决策）/ RealLLM（真实大模型，预留）
        ├── src/tools/    四个业务工具
        └── src/data_store.py  内存数据与草稿状态
```

## 2. ReAct 调用流程

主循环每轮把当前状态（state）交给决策模型，模型返回动作与决策依据，Agent 执行对应工具后把观察结果写回状态，再进入下一轮，直到终结或达到步数上限。

典型路径（以时段冲突素材 M01 为例）：

1. `read_material`：读取素材，信息完整。
2. `check_rules`：规则通过。
3. `query_slot`：请求时段 18:00 已被占用，观察到下一个可用时段 19:00。
4. `query_alternative`：查询 19:00，确认空闲。
5. `request_confirmation`：替代时段需用户确认，返回待确认并结束本轮。
6. 用户确认后再次运行：`save_draft` 保存 19:00 草稿 → `finish`。

## 3. 动态决策动作

| 动作 | 触发条件 | 体现的动态调整 |
|---|---|---|
| recheck_material | 元数据字段缺失 | 先补查而非直接排期 |
| block | 素材不存在/补查失败/规则违规/无可用时段/保存失败 | 安全阻断并说明原因 |
| query_alternative | 请求时段被占用 | 根据冲突观察改用替代时段 |
| request_confirmation | 替代时段未获用户确认 | 守住确认边界 |
| save_draft | 审核通过且时段可用（或用户已确认替代） | 仅保存草稿 |
| finish | 草稿保存成功 | 正常结束 |

## 4. 步数上限保护

- 默认 `max_steps=8`，覆盖所有正常路径（实测正常路径 5~6 步）。
- 达到上限时循环退出，返回 `review_status=incomplete` 与终止原因，不会无限运行。

## 5. 技术取舍

1. **Python 原生实现，不使用 Agent 框架**：题目明确框架不加分。原生实现代码量小、离线可跑、每条决策路径都可解释，也避免把框架的状态机误当成自己的 ReAct 实现。
2. **MockLLM 作为默认决策模型**：保证无密钥、无网络环境下评审仍可复现全部流程；Mock 只验证流程与决策逻辑，不证明真实模型效果，此边界在 03 文档中明确。
3. **RealLLM 仅预留接口**：通过标准库 urllib 调用 OpenAI 兼容 Chat Completions，配置 `LLM_API_KEY` 后启用；未在线验证，作为扩展点而非默认路径。
4. **数据全部内存态**：草稿保存在内存字典中，进程结束即清空，避免任何真实发布或持久化副作用。
